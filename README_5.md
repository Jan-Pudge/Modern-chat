# Домашнє Завдання 13: Локальна Збірка та Деплой Android-додатку (Standalone APK) 🚀📦

Це домашнє завдання є ключовим інженерним етапом розробки мобільного додатку. До цього моменту ви запускали та тестували додаток за допомогою клієнта **Expo Go** (`npx expo start`), де JavaScript-код передавався «по повітрю» через сервер розробника Metro Bundler.

- Базова частина, авторизація та кімнати побудовані у **ДЗ 7** (`lesson-07-module-05/docs-home-work-modern-chat`).
- Редагування/видалення повідомлень, відправка фото у Convex Storage та індикатор набору тексту додані у **ДЗ 8** (`lesson-08-module-05/home-work-08`).
- Відповіді на повідомлення (Swipe-to-Reply) та кастомізація профілів реалізовані у **ДЗ 9** (`lesson-09-module-06/home-work-09`).
- Свайп карток кімнат для видалення реалізовано у **ДЗ 10** (`lesson-10-module-06/home-work-10`).
- Голосові повідомлення (`expo-audio`) та реакції емодзі у реальному часі додані у **ДЗ 11** (`lesson-11-module-07/home-work-11`).
- Відеокружечки (Telegram Video Notes) та курсорна пагінація реалізовані у **ДЗ 12** (`lesson-12-module-07/home-work-12`).

У цьому домашньому завданні ми переходимо від розробки до **продакшн-деплою**:
1. Налаштовуємо локальне нативне середовище (JDK 17, Android SDK) та створюємо **динамічний `app.config.ts`** з підтримкою оточень `development` і `production`.
2. Збираємо справжній **автономний нативний Android-додаток (Standalone APK)** локально на власному комп'ютері — без хмарних черг та зовнішніх сервісів.
3. Встановлюємо APK на фізичний пристрій та перевіряємо **повністю автономну роботу** з базою даних Convex без Metro Bundler.

## 🛠 Стек технологій та інструменти

- **Фреймворк:** React Native (New Architecture) / Expo SDK 52+
- **Мова:** TypeScript
- **Динамічна конфігурація:** `app.config.ts` (Expo Config)
- **Збирач нативного коду:** Gradle 8+
- **Java Platform:** OpenJDK 17 (LTS)
- **Інструменти платформи:** Android SDK Build-Tools, Platform-Tools (`adb`), Command-Line Tools (`sdkmanager`)
- **Бекенд & Realtime DB:** [Convex](https://convex.dev)
- **Автентифікація:** `@convex-dev/auth` (Convex Auth)

## 📋 Чекліст виконання для студента

### 1. Налаштування середовища та конфігурації (Інструкція 01):
- [ ] Встановлено **JDK 17** (перевірено через `javac -version` — має повертати `17.x.x`).
- [ ] Встановлено **Android SDK** через Android Studio або cmdline-tools.
- [ ] Налаштовано змінні середовища `JAVA_HOME`, `ANDROID_HOME` та оновлено `PATH`.
- [ ] `adb --version` успішно виконується з будь-якої папки терміналу.
- [ ] Прийнято ліцензії Android SDK (`yes | sdkmanager --licenses` або через Android Studio).
- [ ] Створено файл `app.config.ts`, який динамічно змінює назву додатку (`Prostir Dev` / `Prostir`) та `packageName` залежно від змінної `APP_ENV`.
- [ ] У файлі `.env.local` наявний коректний `EXPO_PUBLIC_CONVEX_URL`.

### 2. Локальна збірка APK (Інструкція 02):
- [ ] Успішно виконано команду `npx expo prebuild --platform android --clean` (згенеровано папку `/android`).
- [ ] Створено файл `android/local.properties` із правильним шляхом до `sdk.dir`.
- [ ] Перевірено та оптимізовано параметри JVM у `android/gradle.properties`.
- [ ] Успішно скомпільовано APK за допомогою Gradle (`./gradlew assembleDebug` або `./gradlew assembleRelease`).
- [ ] Термінал завершив збірку зі статусом `BUILD SUCCESSFUL`.
- [ ] Знайдено згенерований файл `.apk` у папці `android/app/build/outputs/apk/`.

### 3. Встановлення та тестування на пристрої (Інструкція 03):
- [ ] Фізичний Android-пристрій або емулятор виявляється командою `adb devices`.
- [ ] Додаток успішно встановлено через `adb install -r ...` або пряму передачу APK.
- [ ] Додаток запускається на пристрої автономно **з вимкненим терміналом** (Metro Bundler зупинено).
- [ ] Відображається правильна іконка та назва додатку в лаунчері Android.
- [ ] Працює авторизація та завантаження даних із Convex через мобільний інтернет або Wi-Fi.
- [ ] Запити дозволів на камеру та мікрофон відображаються з коректними текстами.

## 🌟 Бонусні завдання (За бажанням, для додаткових балів)

1. **Збірка автономного Release APK (`assembleRelease`):**
   - Більшість початківців збирають лише Debug APK. Скомпілюйте оптимізований **Release APK** (`./gradlew assembleRelease`), в якому JavaScript бандл повністю запакований всередину APK без налагоджувального коду та Metro-сервера.

2. **Локальна збірка через EAS CLI (`eas build --local`):**
   - Налаштуйте профіль `preview` у `eas.json` та зберіть APK однією командою:
     ```bash
     npx eas-cli build --platform android --profile preview --local
     ```
   - EAS самостійно проведе перевірку середовища, запустить скрипти та покладе готовий `.apk` у корінь проєкту.

3. **Генерація власного релізного ключа Keystore:**
   - Створіть власний ключ підпису за допомогою утиліти `keytool`:
     ```bash
     keytool -genkey -v -keystore my-release-key.keystore -alias my-key-alias -keyalg RSA -keysize 2048 -validity 10000
     ```
   - Налаштуйте блок `signingConfigs.release` у `android/app/build.gradle` для підписаного Release APK.

## 💡 Поради перед початком

- Збірка нативного коду вимагає **4–8 ГБ вільної оперативної пам'яті**. Закрийте зайві важкі програми перед запуском `./gradlew`.
- **Перша компіляція** завжди найтриваліша (5–15 хвилин) — Gradle завантажує залежності та Android NDK/C++ бібліотеки. Наступні збірки будуть значно швидшими (1–2 хвилини) завдяки кешу.
- Якщо виникає помилка `Java heap space` — збільшіть пам'ять у `android/gradle.properties`: `org.gradle.jvmargs=-Xmx4096m`.
- Перевірте що у `.env.local` є валідний `EXPO_PUBLIC_CONVEX_URL` — без нього Release APK не зможе підключитись до бази даних.
- Папку `/android` зазвичай **не додають у Git** (вона в `.gitignore`). Її можна відновити будь-коли командою `npx expo prebuild`.
