## Частина 1: Вимоги та архітектура Push-сповіщень (Інструкція 17)

### 1.1. Ціль та сценарії використання

Мета полягає в інтеграції системних **Push-сповіщень** для платформи Android (з підтримкою iOS) на базі сервісу **Expo Push Notifications** та **Firebase Cloud Messaging (FCM v1)** із реактивним бекендом **Convex**.

#### Ключові сценарії сповіщень:
1. **Нове повідомлення в чаті 💬:**
   - Отримують усі учасники чат-кімнати (крім автора повідомлення).
   - Включає підтримку форматованого прев'ю медіа-повідомлень: `🎤 Голосове повідомлення`, `📹 Відеоповідомлення`, `📷 Фотографія`.
2. **Відповідь на повідомлення (Reply) ↩️:**
   - Персональний пуш автору оригінального повідомлення: *"💬 [Ім'я] відповів(-ла) на ваше повідомлення..."* з цитатою.
3. **Емодзі-реакція на повідомлення 👍❤️🔥:**
   - Пуш автору повідомлення про те, хто і яку реакцію поставив у чаті.
4. **Deep Linking (Глибокі посилання) 🧭:**
   - При кліку на сповіщення в системній шторці або спливаючому банері додаток автоматично відкриває відповідну кімнату: `/(app)/chat/[roomId]`.
   - Працює як у фоновому режимі (Background), так і при холодному старті додатку (Cold Start).

---

### 1.2. Архітектура доставки повідомлень

```
[Клієнт: Дія користувача] 
  │ (Надіслано повідомлення / Відповідь / Емодзі-реакція)
  ▼
[Convex Mutation] (sendMessage, sendMediaMessage, sendAudioMessage, sendVideoNoteMessage, toggleReaction)
  │
  ├─► 1. Збереження сутності в базі даних Convex
  │
  └─► 2. ctx.scheduler.runAfter(0, internal.pushNotifications.sendPushNotification, {...})
        │
        ▼
[Convex Internal Action] (sendPushNotification у середовищі Node.js)
  │
  ▼ HTTP POST (JSON)
[Expo Push Service API] (https://exp.host/--/api/v2/push/send)
  │
  ▼ Авторизація через Service Account Key
[Google Firebase Cloud Messaging (FCM v1) / Apple APNs]
  │
  ▼ Мережевий сокет ОС
[Пристрій користувача] (Системна шторка, вібрація, банер, звук)
  │
  ▼ Тап по сповіщенню
[Deep Linking у usePushNotifications]
  │
  └─► router.push('/(app)/chat/${roomId}')
```

#### Чому використовується `internalAction` та `ctx.scheduler`?
- **Транзакційність Convex:** Мутації (`mutation`) виконуються в детермінованих транзакціях і не мають права здійснювати сторонні мережеві запити (`fetch`).
- **Швидкість інтерфейсу:** Завдяки планувальнику `ctx.scheduler.runAfter(0, ...)` відправка пуш-сповіщення виконується асинхронно у фоні й не затримує відповідь мутації для користувача (Optimistic UI / 0ms delay).
- **Безпека:** `internalAction` доступний лише для виклику зсередини Convex-функцій і не може бути викликаний напряму клієнтом.

### 1.3. Покрокові технічні вимоги

#### 1. Залежності проєкту:
- `expo-notifications`: ядро для роботи зі сповіщеннями на клієнті (*вже є в `package.json`: `~57.0.21`*).
- `expo-constants`: доступ до `projectId` з конфігурації (*вже є в `package.json`: `~57.0.19`*).

#### 2. Конфігурація додатка (`app.config.ts`):
- **Системні дозволи Android:**
  - `"android.permission.POST_NOTIFICATIONS"` (обов'язково для Android 13+ / API 33).
  - `"android.permission.VIBRATE"`.
- **Плагін `expo-notifications`:**
  - Конфігурація кольору (#2563EB), іконки та дефолтного каналу `default`.
- **Firebase Google Services:**
  - `android.googleServicesFile: "./google-services.json"`.
- **EAS Project ID:**
  - `extra.eas.projectId: "<EAS_PROJECT_ID>"`.

#### 3. База даних (`convex/schema.ts`):
- Додати поле `pushToken: v.optional(v.string())` до таблиці `users`.

#### 4. Серверна логіка Convex:
- **`convex/users.ts`:**
  - Створити мутацію `savePushToken({ pushToken: v.string() })` для прив'язки токена поточного користувача.
- **`convex/pushNotifications.ts` (новий файл):**
  - Реалізувати `internalAction` `sendPushNotification`.
  - Валідація токена: перевірка на `ExponentPushToken[...]`.
  - Відправка HTTP POST на `https://exp.host/--/api/v2/push/send` з заголовками та пріоритетом `"high"`.
- **`convex/messages.ts`:**
  - У `sendMessage`, `sendMediaMessage`, `sendAudioMessage`, `sendVideoNoteMessage`:
    - Перевірка `replyToId`: надсилати персональний пуш автору повідомлення, на яке відповіли.
    - Вибірка учасників кімнати (творець кімнати + користувачі, які надсилали повідомлення в цей чат).
    - Запуск `ctx.scheduler.runAfter(0, internal.pushNotifications.sendPushNotification, ...)`.
- **`convex/reactions.ts`:**
  - У `toggleReaction`: надсилати пуш автору повідомлення при додаванні емодзі іншим користувачем.

#### 5. Клієнтська частина та Deep Linking:
- **`hooks/usePushNotifications.ts` (новий хук):**
  - Налаштування `Notifications.setNotificationHandler` (показ банера та звук у Foreground).
  - Налаштування системного каналу Android `default` з максимальною важливістю `Notifications.AndroidImportance.MAX`.
  - Запит дозволу користувача через `Notifications.requestPermissionsAsync()`.
  - Отримання токена через `Notifications.getExpoPushTokenAsync({ projectId })`.
  - Збереження токена в БД через `api.users.savePushToken`.
  - Слухач Foreground: `Notifications.addNotificationReceivedListener`.
  - Слухач фонових кліків: `Notifications.addNotificationResponseReceivedListener`.
  - Обробка холодного старту: `Notifications.useLastNotificationResponse`.
  - Навігація в чат: `router.push('/(app)/chat/${roomId}')`.
- **`components/InitialLayout.tsx`:**
  - Виклик `usePushNotifications()` після успішної перевірки автентифікації (`isAuthenticated === true`).

#### 6. Інфраструктура Firebase та збірка:
- Створення проєкту у Firebase Console з package name `com.modernchat.app` (або `com.modernchat.app.dev`).
- Розміщення `google-services.json` у корені проєкту.
- Генерація приватного ключа Service Account у Firebase та його завантаження в Expo Credentials (FCM v1).
- Збірка через `npx expo run:android` (Development Build) або Standalone APK (Expo Go не підтримує нативні FCM v1 сповіщення).

- **Фактичний стан:** Цю бонусну ідею з ДЗ 9 було винесено в основну програму наступного ДЗ 11 (Інструкція 13). У проєкті повністю реалізовано:

- **Фактичний стан:** У папці `android/app/build/outputs/apk/` наявний лише файл `debug/app-debug.apk` (розміром ~273 МБ). Папка `release/` відсутня.

#### 9. Локальна збірка через EAS CLI (`eas build --local`) (ДЗ 13 / README_5)
- **Вимога:** Конфігураційний файл `eas.json` із профілем `preview` (`"distribution": "internal"`, `"android": { "buildType": "apk" }`).
- **Статус у проєкті:** ❌ **Немає в коді.**
- **Фактичний стан:** Файл `eas.json` у корені проєкту відсутній.

#### 10. Генерація власного релізного ключа Keystore (ДЗ 13 / README_5)
- **Вимога:** Генерація ключа через `keytool`, збереження у `android/app/` та налаштування блоку `signingConfigs.release` у `android/app/build.gradle`.
- **Статус у проєкті:** ❌ **Немає в коді.**
- **Фактичний стан:** У `android/app/` присутній лише стандартний `debug.keystore`. У `build.gradle` блок `release` посилається на налагоджувальний ключ:
  ```groovy
  release {
      signingConfig signingConfigs.debug
  }
  ```

#### 11. Бейдж непрочитаних повідомлень на іконці додатку (ДЗ 14 / README_6)
- **Вимога:** Підрахунок непрочитаних повідомлень та оновлення лічильника на іконці додатку через `Notifications.setBadgeCountAsync(count)`.
- **Статус у проєкті:** ❌ **Немає в коді.**
- **Фактичний стан:** У схемі відсутній трекінг прочитаних повідомлень користувачем (`readBy` або `lastReadAt`), метод `setBadgeCountAsync` не викликається.

#### 12. Вимкнення сповіщень для окремої кімнати (Mute Notifications) (ДЗ 14 / README_6)
- **Вимога:** Прапорець `isMuted` для чату або зв'язки кімната-користувач, перевірка прапорця на бекенді перед відправкою пуша в `convex/messages.ts`, тумблер у налаштуваннях кімнати `settings/[id].tsx`.
- **Статус у проєкті:** ❌ **Немає в коді.**
- **Фактичний стан:** Поле `isMuted` відсутнє у схемі Convex (`chatRooms` / `users`). Сповіщення (після впровадження інструкції 17) розсилатимуться всім учасникам без можливості заглушення окремого чату.

#### 13. Кастомний звук для системного каналу сповіщень (ДЗ 14 / README_6)
- **Вимога:** Додавання кастомного `.wav` або `.mp3` звукового файлу в Android ресурси (`android/app/src/main/res/raw/`) та реєстрація у `Notifications.setNotificationChannelAsync("default", { sound: "custom_sound.wav" })`.
- **Статус у проєкті:** ❌ **Немає в коді.**
- **Фактичний стан:** Канал використовує системний стандартний звук `"sound": "default"`.
